# Plan 001 — Zig 0.16 migration and Tiger Style baseline

## Goal

Move synod to Zig 0.16.0 (source, `build.zig.zon`, CI), install a machine-checked Tiger Style
floor (`zig build tidy`) while the repo is still 270 lines, make the docs honest, ship v0.2.0.

## Why now

The probe (`citadel/realms/synod/STATE.md`) puts synod at **one blocking error class**, entirely
inside `src/main.zig` and `bench/main.zig`: GPA, `argsAlloc`, the `fs.File` stdout writer, and
`time.Timer`. `build.zig` compiles clean against 0.16's `std.Build` (no `linkLibC` fix needed)
and the core passes all 12 module tests under 0.16 untouched — synod's "core never does I/O"
rule kept `std.fs`, `std.net`, `std.time`, `std.Thread` out of `src/`. It is the kingdom's
cheapest migration, and the last moment the Tiger Style floor lands over stubs, not a Raft core.

## Out of scope

- Phase 1 logic (`types`, `log`, `interfaces`, `store`) and after — plan 002; this plan touches
  entry points, build files, docs, and the tidy tool only. `src/adapters.zig` stays a stub.
- **The `wip/*` branch decision: there is none for synod.** `REALM.md` and `STATE.md` record the
  tree as clean at restructure time, so nothing was stashed; no branch to finish or close.

## Risks

- **`zig build test` is a false green.** It reported 13/13 on 0.16 *before* any fix: `zig test`
  never calls `main()`, so lazy analysis skips the broken lines. Mitigation: CI and "Done when"
  gate on `zig build` and `zig test src/main.zig`, never `zig build test` alone.
- **All-zero Tiger Style counts measure a scaffold, not discipline** (STATE.md) — thresholds are
  unproven against real Raft code; expect the ratchet to be argued with in plan 002.
- **Doc reconciliation reads as a regression** — CHANGELOG must say nothing was removed.
- **CI on 0.16 is untested here** — resolving the toolchain from `minimum_zig_version` has never
  run in this repo and the macOS native-link failure behind Linux-only tests is of unknown 0.16
  status; two failed attempts → `needs-human` (`citadel/protocol/GITHUB.md`). Benchmark drift
  there is not a bug: LLVM loop vectorization is off in 0.16.
